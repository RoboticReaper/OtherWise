# Research: unfamiliar, connected discovery

Checked 2026-10-07. This note separates established source facts, repository observations, and proposed experiments. It does not establish a winning recommender.

Later clarification: the [current evaluation design](recommendation-evaluation.md) and [spec](superpowers/specs/2026-10-07-recommendation-system-design.md) use four automated proxy scorecards and per-metric champions. Human trials are optional; the user authorized a small initial rubric check. Human evaluation described below is a validation track, not a prerequisite for the experiment loop.

The current catalog is a useful, reproducible starting point: its entries have descriptions and provenance. The category graph supplies inspectable connections. Their adequacy depends on whether people receive unfamiliar, connected ideas they want to explore. Distance and graph paths alone cannot answer that question. Foundational recommender research argues for evaluating user usefulness beyond accuracy; that argument also cautions against equating an attractive geometric score with discovery quality. [McNee, Riedl and Konstan, 2006](https://grouplens.org/site-content/uploads/accurate-CHI-20061.pdf).

## What the current system actually represents

The checked-in broad catalog has 3,452 entries: 718 authored interests plus 2,734 Wikidata entries selected from Wikimedia's expanded essential-articles list. The graph contains **3,642 unique concepts**, selected 3,680 times across 69 areas; shared concepts explain the difference. Equal domain budgets constrain this sample, rather than establishing completeness or neutrality. [Catalog notes](../data/README.md), [graph notes](../data/discovery_graph_README.md), [Wikimedia selection source](https://meta.wikimedia.org/wiki/List_of_articles_every_Wikipedia_should_have/Expanded).

Broad ranking favors the midpoint of an angular-distance band and penalizes similarity to already selected results. Exact catalog titles receive their descriptions; other inputs remain raw phrases. Specific discovery routes interests and broad results into eight areas, follows observed category paths, then enforces the band and reranks. Consequently, an eligible concept outside the selected areas is unavailable regardless of its eventual score. This is an implementation deduction, not a measured failure rate. [Input and broad ranking](../explorer.py), [routing](../service/discovery.py), [graph ranking](../graph_explorer.py).

## Concept identity, word senses, and uncertain inputs

Wikidata QIDs identify concepts, objects, or instances. Labels are not unique; descriptions disambiguate them, and multiple items may share an alias. Alias matching must therefore return candidate IDs rather than silently choose one. WordNet addresses a different problem: common English word meanings belong to distinct synonym sets, with glosses, semantic relations, and a distinction between types and instances. It can help distinguish senses of “bank,” but it is not a complete catalog of hobbies, named entities, scientific topics, or emerging practices. [Wikidata items](https://www.wikidata.org/wiki/Help:Items), [aliases](https://www.wikidata.org/wiki/Help:Aliases), [Princeton WordNet](https://wordnet.princeton.edu/).

**Proposal:** represent a concept using an ID, label, description, aliases, language, source revision, and explicit type when available. Use QIDs where present and stable local IDs for authored concepts. Permit two concepts with the same display label. Preserve aliases as lookup metadata, not as additional recommendations. Keep WordNet sense IDs distinct from Wikidata entity IDs; linking them requires evidence.

Resolve an interest from its phrase plus context the user explicitly supplies: “bass guitar” and “bass fishing” are different requests. Context may rank interpretations without proving one. When candidates remain close, preserve several interpretations or offer a brief sense choice; retain an unresolved phrase when none is supported. Avoid averaging competing senses into one vector and excluding both neighborhoods as “known.” An exact label match should not override ambiguity. Similarity margins are diagnostic scores, not calibrated probabilities. Measure resolution errors, abstentions, and clarification burden separately from recommendation quality.

## Coverage and retrieval

An absent synonym is a lookup problem; an absent concept is a coverage problem. Adding aliases can solve the first without solving the second. A word absent from the catalog may still retrieve related entries through embeddings, but a fixed catalog cannot recommend a concept it does not contain.

**Proposal:** expand from documented gaps in development inputs, using bounded source retrieval and review. Require a real source ID or documented authored provenance, a useful description, source URL/revision where available, and a concept-type check. Deduplicate by identity, retain multiple senses, and inspect practical-interest and cultural gaps. Record rejected and unresolved candidates. Generated text may suggest a search or editorial hook, but cannot become an unsupported concept or source claim. Keep expansion separate from algorithm comparisons and reserve untouched inputs to test whether coverage generalizes.

Wikipedia categorization organizes articles through multiple parent categories and several overlapping schemes, such as artist, date, and genre. The category-membership API records membership; it supplies no prerequisite or difficulty semantics. Treat paths as provenance and navigation, with typed Wikidata relations retained separately when imported. The claim that a path is a useful learning connection requires review. [Wikipedia categorization guidance](https://en.wikipedia.org/wiki/Wikipedia:Categorization), [membership API](https://www.mediawiki.org/wiki/API:Categorymembers).

**Proposal:** first test full-catalog dense retrieval with the existing MPNet vectors. Then combine it with lexical retrieval over titles, aliases, and descriptions. SQLite FTS5 provides a local BM25 implementation when enabled; exact identity matches should remain explicit. Reciprocal rank fusion (RRF) combines ranked lists without assuming BM25 and cosine scores have comparable scales. Its original retrieval experiments support it as a baseline, not as a guaranteed discovery improvement. BEIR likewise found BM25 robust across heterogeneous retrieval tasks, rather than finding one universally superior neural model. [SQLite FTS5](https://sqlite.org/fts5.html#the_bm25_function), [Cormack, Clarke and Büttcher, 2009](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf), [Thakur et al., 2021](https://arxiv.org/abs/2104.08663).

For the main experiment, apply current eligibility rules before ranking and preserve radius, expansion, overlap, known exclusions, and overlap caps. Fuse ranks within that eligible pool; nearest-neighbor retrieval performed before filtering could omit the outward band. Use graph membership as an optional candidate source or feature, rather than a mandatory gate. Compare a relevance-and-band score followed by a redundancy penalty. MMR supplies the foundational relevance/diversity tradeoff; it does not establish that diversity equals curiosity or novelty. [Carbonell and Goldstein, 1998](https://www.cs.cmu.edu/~jgc/publication/MMR_DiversityBased_Reranking_SIGIR_1998.pdf).

This scale warrants measuring exact matrix search before introducing approximate indexes. Keep local MPNet as the first model. Short keywords against longer descriptions are an asymmetric retrieval setting, which Sentence Transformers distinguishes from symmetric similarity. A later, optional model trial could use English `e5-small-v2` (384 dimensions) with its required query/passage prefixes. Its score distribution differs, so MPNet radius values must not transfer without calibration and revised explanations. A cross-encoder could rerank a bounded pool, with additional per-pair inference cost. Neither model option is a proven improvement for this application; do not download either merely to assume one. [Search guidance](https://sbert.net/examples/sentence_transformer/applications/semantic-search/README.html), [E5 model card](https://huggingface.co/intfloat/e5-small-v2), [retrieve/rerank guidance](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html).

**Optional external challengers:** the user permits external AI services when quality improves. Compare externally assisted sense resolution and grounded candidate reranking separately against local variants. Supply fixed context and sourced candidate descriptions, require existing IDs, retain uncertainty, and reject invented IDs or unsupported explanations. Keep the prompt and model version fixed and record dollars per request, latency, failures, and information sent. Test external source-assisted expansion on a separate catalog snapshot. General model benchmarks do not prove curiosity gains, and an external model's self-evaluation cannot replace blind human judgments. No billable calls are needed to design these trials.

## What would count as good?

Interestingness needs user evidence. Novelty concerns unfamiliarity to this person; unexpectedness concerns what they would have anticipated; diversity concerns differences among results. These can diverge. Serendipity research explicitly combines novelty, relevance, and unexpectedness, while noting competing definitions. [Kotkov, Veijalainen and Wang, 2017](https://www.scitepress.org/Papers/2017/62328/62328.pdf).

**Proposed primary outcome:** for each participant and request, collect separate 0–3 ratings for connectedness to their intended interest, unfamiliarity, curiosity to explore, and accessibility at their current level. Higher is better on every scale. Define a qualified item as scoring at least 2 on all four dimensions and passing wrong-sense, source/provenance, and duplicate checks. Define **QualifiedDiscovery@k = qualified distinct items / requested k**. Missing slots count as unqualified. Report results per participant before averaging across participants. These thresholds and this metric are product design choices, not scientifically calibrated constants.

Report each dimension separately, list preference, unexpectedness, wrong-sense/source failure rates, duplicate rate, candidate coverage, and empty-list rate. Track semantic intra-list distance and domain coverage as diagnostics, without rewarding disconnected randomness. Later voluntary exploration can supply corroborating evidence; clicks alone do not establish learning or usefulness. Hard source and identity checks are necessary correctness gates but cannot judge personal curiosity.

Unlabeled semantic scores cannot choose the “best interesting recommender.” Ranking and evaluation with the same embedding distance rewards the objective already encoded in that representation. Invented users, model-generated relevance labels, and a few curated examples can reveal bugs, but cannot establish human benefit. A system can score well while recommending known, inaccessible, or wrong-sense ideas.

Collect participant-approved phrases spanning ambiguity, niche interests, unfamiliar topics, short and contextual inputs, and multiple interests. Pool and deduplicate candidates from all variants; randomize item order and hide algorithm names. Use identical descriptions and presentation so a better hook does not masquerade as a better ranker. Obtain each participant's familiarity judgment on first exposure. For list comparisons, randomize left/right placement, permit ties and “neither,” and counterbalance order to limit first-list exposure effects.

Split development and final evaluation by participant, keeping related paraphrases together. Freeze thresholds, weights, catalog, prompts, and seeds before final judging. Keep final curiosity/familiarity labels out of tuning, catalog expansion, prompt examples, and reranking. Public descriptions are legitimate retrieval inputs; held-out judgments are not. If learning from historical feedback later, respect the global timeline and information available at prediction time; temporal leakage can change recommender rankings. Report paired differences with uncertainty clustered by participant, and avoid declaring a winner from a small convenience sample. [Ji et al., 2020](https://arxiv.org/abs/2010.11060).

## Focused experiment matrix

Use the same graph concepts for A–D, with identical input/context snapshots, MPNet revision, descriptions, controls, and feedback available before each request.

| Variant | Change | Question isolated |
|---|---|---|
| A | Current eight-area graph routing and band ranking | Reproducible baseline |
| B | All graph concepts, otherwise A's eligibility and ranking | Does routing lose useful candidates? |
| C | B plus lexical/dense rank fusion and relevance/diversity ranking | Does hybrid ranking help within the promised band? |
| D | C plus context-aware, uncertainty-preserving input resolution | Does resolution reduce wrong-sense results? |

For C, ablate lexical fusion, relevance weighting, and diversity separately. For D, ablate contextual resolution. Keep catalog expansion as a second comparison on a fixed expanded snapshot; compare algorithms on both snapshots so data gains and ranking gains remain distinguishable. Test adaptive novelty without a hard band only as a separately named experimental mode with explicit controls; never silently relax existing sliders.

Add external resolution to C as E1 and external reranking to C as E2, changing one stage at a time. Hold candidate identity and provenance constant for these comparisons.

Record candidate counts, source routes, seed stability, warm latency p50/p95, cold startup, embedding rebuild time, memory, and disk/model bytes on the same device. Select using held-out QualifiedDiscovery@k and blind preference, subject to correctness and agreed resource limits. If results conflict or uncertainty is large, retain the baseline and identify the unresolved tradeoff. The initial investment should be identity, coverage diagnostics, and human evaluation before larger models or a more elaborate graph.
