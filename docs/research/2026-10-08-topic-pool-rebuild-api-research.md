# OtherWise 主题池重做：OpenAI API 成本与工作流调查

核查日期：2026-10-08。范围：官方 API 文档、透明费用估算和当前本地源码/目录检查；未调用付费 API，未修改主题池或运行代码。检查对象是当前工作区（包含已有未提交改动），不是已发布版本。

## 判断

用模型批量重写描述或生成候选主题可行。调用费很可能远低于分类设计、查重、事实核查与迁移的人工成本。建议先用 500 个分层样本比较“保留主题重写描述”和“重新生成主题”，确认实际收益后扩大；不能把统一文风当作主题质量或推荐质量已经提高的证据。以下建议为工程判断，并非 OpenAI 对该项目的质量保证。

## 生成成本：只算一遍基础生成

假设每个主题平均 **150 输入 token + 200 输出 token**；输入含摊销后的规则和种子资料，输出含名称、描述及结构字段。采用短上下文、标准速率、不缓存、不使用搜索；计算式：`条数 × (150 × 输入单价 + 200 × 输出单价) / 1,000,000`。这里的 200 输出 token 假定没有额外推理 token，若开启推理则需追加。Token 不是单词数；双语、多字段、较长事实材料会增加用量。

| 模型 | 输入 / 输出美元每百万 token | 500 条 | 5,000 条 | 31,637 条 |
|---|---:|---:|---:|---:|
| GPT-6 Luna | $0.10 / $0.50 | $0.058 | $0.58 | $3.64 |
| GPT-5.4 Mini | $0.75 / $4.50 | $0.51 | $5.06 | $32.03 |
| GPT-6.1 Sol | $2.00 / $10.00 | $1.15 | $11.50 | $72.77 |

价格来自已打开核查的 [API 定价页](https://developers.openai.com/api/docs/pricing)、[GPT-6 Luna 模型页](https://developers.openai.com/api/docs/models/gpt-6-luna) 和 [GPT-5.4 Mini 模型页](https://developers.openai.com/api/docs/models/gpt-5.4-mini)。这三个模型用于展示费用跨度；本调查没有实测哪一个能满足 OtherWise 的质量标准，也没有确认当前账户权限。不能因为名字更新或价格更高便预设胜出。

上表**不包含**第二遍审核、失败重试、去重后的补生成、推理、网页查证、人工检查或基础设施。若同样工作完整做两遍，基础生成费约翻倍。推理 token 虽不可见仍按输出计费，实际应查每个任务返回的 usage。[Reasoning models](https://developers.openai.com/api/docs/guides/reasoning)

如每条额外调用一次网页搜索，31,637 条仅工具调用费就约 $316.37，另加搜索内容与模型 token；不应将“每条有来源的核查”放进几美元的纯生成预算。[API 工具定价](https://developers.openai.com/api/docs/pricing)

## Batch 与时间

适合离线处理的 Batch 在标准价基础上便宜 50%；因此上表三种模型的基础生成费用均可再减半。单批最多 50,000 请求、200 MB；embedding 单批另限制最多 50,000 输入。官方处理窗口为 24 小时，可能更快，但也需处理过期请求、错误与重提。[Batch API](https://developers.openai.com/api/docs/guides/batch)

31,637 条可以装入一个批次的数量上限内，但文件大小、排队 token 限额及账户权限仍须实际核对。生成后再审核、再 embedding 是相互依赖的阶段；不能把整个项目承诺为一天完成。人工若每条仅看 30 秒，500 / 5,000 / 31,637 条也分别需约 **4.2 / 41.7 / 263.6 小时**，且不含查资料。因此适合自动检查全部记录，再分层抽样与检查被标记的问题；需要完整事实认证时预算应单独估计。

## Embedding 另算；重写描述不要求更换模型

若未来选择 OpenAI embedding，假设每条嵌入文本 100–200 token，一次全量计算的标准 API 费如下：

| 模型 | 美元每百万输入 token | 500 条 | 5,000 条 | 31,637 条 |
|---|---:|---:|---:|---:|
| text-embedding-3-small | $0.02 | $0.001–0.002 | $0.01–0.02 | $0.063–0.127 |
| text-embedding-3-large | $0.13 | $0.0065–0.013 | $0.065–0.13 | $0.411–0.823 |

官方价格：[small 模型页](https://developers.openai.com/api/docs/models/text-embedding-3-small)、[large 模型页](https://developers.openai.com/api/docs/models/text-embedding-3-large)。Batch 支持 embedding 并有 50% 折扣。

默认 small 为 1536 维、large 为 3072 维，可用 dimensions 参数降低维度；向量可用于相似度、推荐与聚类。[Embeddings 指南](https://developers.openai.com/api/docs/guides/embeddings)

工程推论：向量维度相同不代表语义坐标相同。改 embedding 模型时，所有互相比较的主题、兴趣、概念与区域向量都应按相同模型和文本规则重新计算，不能直接混用旧新向量。即使保留原模型，描述改动后也应重算对应向量与依赖的邻居、聚类、布局。以上 OpenAI embedding 费用是可选替代方案的估算；**不是 OtherWise 当前本地 embedding 的收费**。

## ChatGPT 与批量 API 的分工

ChatGPT 适合讨论主题标准、写几十条范例和人工审阅。大量生产更适合按独立记录编排 API：保存请求与结果、给条目稳定 ID、使用固定 schema、断点续跑、记录版本并只重试失败条目。这是工作流建议，不是说 ChatGPT 完全不能处理文件。API token 价格与 ChatGPT 订阅使用分开计算，不能拿上表预测订阅可做多少任务。[ChatGPT 定价说明](https://learn.chatgpt.com/docs/pricing)

Structured Outputs 能约束 JSON schema，适合统一字段格式，但仍可能生成内容错误；格式合规不能证明真实、无重复、类别平衡或适合作为兴趣。[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

## 推荐试点验收

从全部领域抽取 500 条，为小领域保留最低样本量，同时覆盖短描述、相近主题、含糊主题及正常条目。给同一批种子分别生成保留 ID 的描述改写版与新主题候选版，盲评清晰度、事实正确性、主题粒度、重复率与可探索性。再用现有 embedding 流程比较近邻是否更合理；保留原库快照与原 ID 映射。若只是描述改写就明显改善，先做这一层；从零换整个主题集合需要额外证明覆盖率、用户状态映射和推荐收益。

## 当前目录的有限质量检查

粒度为每条一个 topic。直接读取 [topics.json](../../data/topics.json)，共 31,637 条、23 个领域；来源为 Wikidata 30,919 条、自编 ProductSpace 718 条。目录文件字节 SHA-256 为 `210e2d4a080a90cd0acbb7116dd547e1573971102c60651f728527c0df3a995f`，用于标识本次检查快照，不等同于程序的规范化目录 hash。

| 检查 | 观测 | 判断及限制 |
|---|---:|---|
| topic/domain/description 缺失或空白 | 0 | 基本字段完整；不证明语义正确 |
| 按 explorer._key 规则归一化后的标题重复超额 | 0 | 未发现该规则下同名；未做同义/语义去重 |
| 已有 Wikidata ID 重复超额 | 0 | 实体 ID 无重复；不证明粒度一致 |
| 描述英文空白分词中位数 | 7 词 | 许多描述更像实体辨识标签，可能不足以支持兴趣探索 |
| 描述少于 8 词 | 16,764，52.99% | 筛查线索，不是错误率或必须重写比例 |
| 完全相同描述 aspect of history | 366 | 缺少区别性信息，是优先人工抽查对象 |
| 完全相同描述 species of plant | 211 | 分类可以正确，但不能单凭此说明具体兴趣价值 |

Geography & travel 有 5,049 条，Mind & behavior 236 条；这种计数差异说明来源和选择偏向，不足以推断推荐曝光不平衡或要求所有领域等量。只有当前快照的有限检查，未测量质量变化趋势、全库事实错误率、用户满意度或真实推荐收益。

复算口径：`rows=json.load(...)`；长度为 `len(row['description'].split())`；标题去重按源码 `_key`（strip、casefold、空格/下划线/连接符统一），QID 仅统计非空字段；重复描述使用完整字符串计数。未调用模型做内容评分。

## Embedding 和功能兼容性：当前源码证据

- [explorer.py](../../explorer.py#L13) 使用 `sentence-transformers/all-mpnet-base-v2`；[topic_texts / interest_texts](../../explorer.py#L57) 嵌入 `topic: description`，精确命中的兴趣也采用目录描述。本地模型缓存配置 max_seq_length 为 384，写成长文章可能截断；建议先用 30–60 个英文词的事实描述作为待测起点，而不是越长越好。
- [service/engine.py](../../service/engine.py#L63) 缓存键包含模型与整库文本。当前实现只要文本改变即产生新键，缓存缺失时编码全库；没有自动按条目复用不变向量。应离线预生成，避免上线时首次启动等待全量编码。
- [extension/core/index.js](../../extension/core/index.js#L107) 和 [scripts/build_extension.py](../../scripts/build_extension.py#L26) 把标题作为 ID。改名、合并或删除会影响已保存兴趣、浏览证据、探索记录及地图节点关联；保留旧标题是第一阶段低风险办法。未来稳定 ID 与 display title 解耦须同时迁移状态和接口，不能只给 JSON 新增 id 就认为完成。
- [galaxy/validation.py](../../galaxy/validation.py#L15) 对所有目录字段和行顺序计算指纹，打包时拒绝陈旧布局；[service/engine.py](../../service/engine.py#L109) 与 [focus-contract.js](../../extension/core/focus-contract.js#L18) 核对目录/模型/向量身份。目录、embedding、Galaxy 坐标与高维近邻、extension 包、后端必须作为一致版本发布；离线 Focus 演示也需检查并重新录制。仅替换 topics.json 不够。
- [service/api.py](../../service/api.py#L98)、[galaxy/preprocessing.py](../../galaxy/preprocessing.py#L238) 与前端 Focus 合同目前约束 768 维。更换 embedding 模型是另一个迁移任务，降为相同维数也不能混用向量空间。
- [service/discovery.py](../../service/discovery.py#L52) 另读 discovery_graph.json，有 3,642 概念及 69 areas（见 [图目录说明](../../data/discovery_graph_README.md)）。更换主池不会自动改善该图的描述；其推荐也依赖 broad 向量选区域。应审核重叠标题语义、concept/area IDs、来源路径和反馈保留；不要用模型虚构关系来替换有证据的图边。

保持现有 MPNet 时，重算没有按 token 收取的 API 费；仍有本机计算、存储和等待成本。本轮没有实际编码/布局测速，因此不提供机器耗时保证。修改描述后推荐结果、距离分布、近邻与地图形状变化是预期行为；“不影响现有功能”应定义为功能可用和状态保留，并允许经过评估的结果变化。

## 方案取舍与建议进度

| 路线 | 收益 | 代价/风险 | 建议 |
|---|---|---|---|
| 原主题和来源不动，修复差描述 | ID 兼容较好；保留长尾覆盖 | 不能解决不合适的主题选择；仍须重建派生资源 | 首选对照组和第一阶段 |
| 人工设计主题标准，现有来源+模型补充核心库 | 可控制粒度、领域和可探索性 | 需要选题审核及别名映射 | 若第一阶段不足，逐步建立 |
| 模型从零自由生成同规模全库 | 写作风格统一、候选生产快 | 覆盖无依据、同义重复、事实幻觉、训练分布偏向、状态迁移 | 当前不建议直接替换 |

初步工程估算（非已测量工期）：500 条对照试点约 12–24 人时，含规则、生成、人工抽查、固定种子评测，通常分几天到一周；全库正式迁移另预留约 2–5 个工程工作日，复杂 ID 迁移可能更长。完整内容审核另算：5,000 条最低 41.7 人时、31,637 条最低 263.6 人时（按每条 30 秒，尚未查证）。两位学生兼职推进，全库可信重建合理按数周至数月规划。抽样审核可降低工作量，但必须保留未审标记，不宣称全库经过事实认证。

先统一“值得探索的 topic”标准和粒度；基于真实来源写简短中性描述，将来源事实、AI 编辑版本和审核状态分开记录。不要把营销式 hook、同一套套话或堆叠关键词直接当作 embedding 文本。先保留当前英文 embedding 输入，中文展示如需要应另存，避免同时改变语言、模型和主题三项因素。

对照试点保留旧库、新描述库、新候选库。固定一组跨领域兴趣输入、随机种子和参数，在完整候选背景中比较：人工描述盲评、语义近邻合理性、实际边界带推荐的可探索性、返回不足 10 条的比例、同义重复率，以及旧兴趣映射保留率。只在 500 条孤立小库中测推荐，会把候选密度变化混进质量结论。试点改写可先替换完整库中的 500 条；缩小主池需另测稀疏距离带。

批准的候选先离线生成所有派生资源并通过迁移测试，再同步切换后端/扩展，保留旧库、旧向量与旧包回滚。若不能同步更新旧客户端，需要版本化服务兼容方案；当前身份检查本身不会提供双版本服务。上述是建议，尚未实施或验证迁移。
